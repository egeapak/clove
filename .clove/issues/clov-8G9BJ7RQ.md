crates/clove-import/src/sync_net.rs push_create() and push_update() send item.body to GitHub, then record export_fingerprint(item), the fingerprint of the body that was sent. They never compare it with the body in GitHub's response (created.body / the PATCH response). A proxy or GitHub App can change the body on the way. For example, an egress proxy appends a '---\n_Generated by [Claude Code](...)_' footer to every issue and comment body. The altered body stays on GitHub, and it comes back into the local item on the next pull after the issue changes on GitHub. Eight local items already carry that footer: clov-03HSZVB9 clov-0SEJR3ZG clov-24GBXFJ3 clov-4K6SMY5F clov-6RC64GSZ clov-E9RPYPEQ clov-Q3736PTQ clov-YCZZ7GS6.

Expected: after a push create or update, if the response body does not equal the sent body, sync edits the GitHub issue so its body matches the local body, and the report says so. If the edited body still does not match (the same proxy changes the PATCH too), sync stops retrying, reports a warning that names the issue, and does not loop on later runs. Comments need the same check (apply_comment_threads).

Also remove the footer from the eight local items above, so the next push writes the clean body to GitHub.

Done when: a test in crates/clove/tests/sync_github.rs has the mock server append text to created and updated bodies, and asserts that sync edits the issue back, warns when the edit is also changed, and that a second sync makes no further calls; and the eight items have no footer.
